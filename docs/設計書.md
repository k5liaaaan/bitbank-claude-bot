## 1. プロジェクト概要

### 目的
bitbank APIとClaude AIを組み合わせた、Dockerで動作するBTC/JPY自動取引ツール。
Mac / Windows どちらでも Docker Desktop があれば動作する。

### 利用イメージ

```
ユーザー
  │
  ├─ VSCode / Claude Code
  │     └─ 取引指示・ルール変更
  │
  └─ ブラウザ (http://localhost:8080)
        └─ ダーク系リッチUI
              ├─ 価格・残高のリアルタイム更新（WebSocket）
              ├─ ボットログのライブストリーム
              └─ APIキー・設定管理
```

### 起動方法

**Windows:** `start.bat` をダブルクリック  
**Mac:** ターミナルで `./start.sh`（または Finderからstart.shをダブルクリック）

内部では `docker compose up -d` が実行され、ブラウザが自動で開く。

### 前提条件
- Docker Desktop がインストールされていること（[docker.com](https://www.docker.com/products/docker-desktop/)）
- インターネット接続（初回のみイメージのダウンロードが必要）
- bitbank APIキー（取引権限付き）
- Anthropic APIキー

### スコープ（初期リリース）
- BTC/JPY の現物取引のみ
- Claudeによる売買シグナル判断（取引ルールMDに基づく）
- WebSocketによるリアルタイムUI（価格・残高・ログ）
- ブラウザでの資産状況・取引履歴・資産推移グラフ確認（ダーク系リッチUI）
- ブラウザでのAPIキー・設定管理（グローバルストップの基準資産も手動設定）
- ドライランモード（実際には注文しないシミュレーション、デフォルト: ON）
- 取引履歴・ログの1年保存（自動パージ）
- Mac / Windows 両対応

### スコープ外（初期リリース）
- Slack連携
- OS通知（Windows/Macトースト）
- レバレッジ・先物取引
- BTC/JPY以外の通貨ペア
- バックテスト機能

### リアルタイムデータフロー

```
bitbank WebSocket
  └─▶ api コンテナ（価格受信）
        └─▶ Redis pub/sub（"price" チャンネル）
              └─▶ ブラウザ（WebSocket接続中の全クライアントへ配信）
                    └─▶ 価格・残高をリアルタイム更新

ボットログ
  └─▶ api コンテナ（ログ生成）
        └─▶ Redis pub/sub（"logs" チャンネル）
              └─▶ ブラウザ ログ画面へストリーミング
```

### 自動取引サイクル（15分ごと）

```
1. Redis キャッシュから最新価格取得（bitbank WS経由で常時更新済み）
2. bitbank REST API → 残高取得
3. SQLite → 直近取引履歴・保有状況
4. 上記 + trading_rules.md → Claude API（プロンプトキャッシュ有効）
5. Claude → {action: "buy"|"sell"|"hold", reason: "..."}
6. グローバルストップチェック（設定した基準資産比 -X% を超えていれば強制 hold）
7. buy/sell の場合 → bitbank 注文送信
   （DRY_RUN=true の場合は注文しない、ログのみ記録）
8. 結果を SQLite へ記録・Redis 経由でブラウザへ通知
```

### 4-2. グローバルストップ設計

```python
# 設定例（ブラウザUIで設定）
global_stop = {
    "base_asset_jpy": 100000,  # 基準総資産額（ユーザーが手動入力）
    "stop_loss_pct": 20,       # 基準資産比 -20% で停止
    "enabled": True
}

# 判定ロジック
def is_global_stop_triggered(current_total_jpy: float, config: dict) -> bool:
    if not config["enabled"]:
        return False
    base = config["base_asset_jpy"]
    threshold = base * (1 - config["stop_loss_pct"] / 100)
    return current_total_jpy <= threshold
```

### 4-3. Claude プロンプト設計（プロンプトキャッシュ活用）

```python
# trading_rules.md の部分をキャッシュ（変更頻度が低い）
messages = [

            },

                "type": "text",

```

## 7. セキュリティ設計

### APIキー管理フロー

```
ブラウザ設定画面でキーを入力
  ↓
POST /api/settings → FastAPI（127.0.0.1:8080のみバインド）
  ↓
.env ファイルへ書き込み
  ↓
.gitignore で git 追跡対象外
```

### .gitignore 必須項目

```gitignore
.env
data/
__pycache__/
*.pyc
*.pyo
```

### docker-compose.yml セキュリティ設定

```yaml
services:
  api:
    ports:
      - "127.0.0.1:8080:8080"   # localhost のみバインド（外部非公開）
  redis:
    ports:
      - "127.0.0.1:6379:6379"   # localhost のみ
```

### 起動スクリプト（start.bat / start.sh）の処理

```
1. .env ファイルの存在確認（なければ .env.example からコピーして案内）
2. docker compose up -d（バックグラウンドで起動）
3. 起動完了を待機（ヘルスチェック）
4. ブラウザで http://localhost:8080 を自動オープン
```

## 8. 設定ファイル設計

### .env.example

```env
# ===== bitbank APIキー =====
# bitbank管理画面 > API管理 で取得（取引権限を有効にすること）
BITBANK_API_KEY=your_api_key_here
BITBANK_API_SECRET=your_api_secret_here

# ===== Claude APIキー =====
# console.anthropic.com で取得
ANTHROPIC_API_KEY=your_claude_api_key_here

# ===== 取引設定 =====
DRY_RUN=true                    # true=シミュレーション / false=本番取引
POLLING_INTERVAL_MINUTES=15     # Claude判断の間隔（分）
LOG_RETENTION_DAYS=365          # ログ・履歴の保存期間

# ===== サーバー設定（通常変更不要） =====
SERVER_PORT=8080
```

### docker-compose.yml

```yaml
version: '3.8'

services:
  api:
    build: ./src/server
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./data:/app/data          # SQLite永続化
      - ./config:/app/config      # trading_rules.md
      - ./.env:/app/.env
      - ./src/web:/app/web        # 静的ファイル
    depends_on:
      redis:
        condition: service_healthy
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    ports:
      - "127.0.0.1:6379:6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
    restart: unless-stopped
```

### config/trading_rules.md

```markdown
# BTC/JPY 取引ルール

## 基本設定
- 取引ペア: BTC/JPY
- 1回の最大購入額: 10,000 JPY
- 1日の最大取引額: 50,000 JPY

## リスク管理
- 損切りライン: -5%（個別ポジションの購入価格比）
- 利確ライン: +10%（購入価格比）
- グローバルストップ損失率: 20%
  ※ 基準資産額はブラウザの設定画面で手動設定してください
- 急変動停止: 1時間で±10%以上の価格変動があった場合は取引停止

## Claudeへの取引指示
あなたは慎重な暗号通貨トレーダーとして行動してください。
利益確保を優先し、大きなリスクは避けてください。
確信が持てない場合は必ず「hold」を選んでください。

## 買いシグナル（参考）
- 24時間価格変動が-5%以上の下落（押し目買い）
- 出来高が直近平均の1.5倍以上

## 売りシグナル（参考）
- 利確ライン（+10%）に到達
- 損切りライン（-5%）に到達

## 取引禁止時間帯
- 毎日 22:00〜08:00（JST）は取引しない
```

## 10. コスト試算

### Claude API（claude-sonnet-4-6）

| 項目 | 通常 | プロンプトキャッシュ適用後 |
|-----|------|------------------------|
| 入力単価 | $3 / 1M tokens | $0.30 / 1M tokens（90%OFF） |
| 出力単価 | $15 / 1M tokens | $15 / 1M tokens（変わらず） |
| 1回入力 | 約3,000 tokens | ルールMD(2,000)がキャッシュ → 実質1,000 tokens |
| 1回出力 | 約200 tokens | 変わらず |
| 呼出回数 | 96回/日（15分ごと） | 同じ |
| **日次コスト** | **約$1.15/日** | **約$0.32/日** |
| **月次コスト** | **約¥5,200/月** | **約¥1,450/月** |

→ **プロンプトキャッシュを有効化することで月額約¥1,500程度が目安**

### Docker / インフラコスト
- ローカル実行のためサーバー費用なし
- Redis: 軽量（メモリ使用量 < 50MB）
- SQLite: 1年分のデータで数十MB程度
